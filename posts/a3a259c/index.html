Introduction to Bluetooth

Bluetooth is a widely used wireless communication technology that has evolved over the years. This overview will provide insights into its history, core concepts, architecture, and practical applications.

Bluetooth Version History

The evolution of Bluetooth technology is marked by several key versions:

Version Release Year Major Updates
4.0 (Low Energy) 2010 - Introduced Bluetooth Low Energy (BLE) for IoT and wearable devices.
4.1 2013 - Improved interference with LTE. - BLE devices can act as both master and slave.
4.2 2014 - Increased data transfer speed (10x packet capacity). - Supported IPv6, enhancing IoT applications.
5.0 2016 - Increased data transfer speed to 2 Mbps. - Extended range up to 4 times. - Enhanced broadcast capacity for Beacon applications.
5.1 2019 - Direction finding (AoA/AoD) for improved indoor positioning.
5.2 2020 - LE Audio with support for LC3 audio codec. - Enhanced Attribute Protocol (EATT) for improved BLE connection efficiency.
5.3 2021 - Improved BLE connection reliability. - Enhanced power management for longer battery life.
5.4 2023 - Periodic Advertising with Response (PAwR) for better broadcast performance. - Encrypted Advertising Data for enhanced security.
6.0 2024 - Channel Sounding for centimeter-level distance measurement. - Decision-based advertising filtering for improved scanning efficiency. - Enhanced Isochronous Adaptation Layer (ISOAL).

Core Concepts: BR/EDR and BLE

When exploring Bluetooth specifications, you will often encounter two key terms:

  • BR/EDR - Basic Rate/Enhanced Data Rate
  • BLE - Bluetooth Low Energy

These terms represent different implementations of Bluetooth technology, each with distinct physical implementations and channel management methods.

Profiles vs Protocols

In specifications, you will also find two important terms:

  • Profile - Represents a set of services or functionalities that standardize communication methods and states between devices. It describes how to use a feature, including state information. This is referred to as a specification or configuration.
  • Protocol - Similar to the common HTTP Protocol in networking, it defines how devices exchange data through packet definitions. It specifies packet structure, transmission methods, and communication sequences. This is referred to as a protocol.

Bluetooth Architecture

The architecture of Bluetooth is similar to general network structures, comprising a physical layer and higher-level stacks. The HCI (Host Controller Interface) serves as the boundary between the software stack and hardware control layers.

HCI corresponds to the HAL (Hardware Abstract Layer) in the system, responsible for handling driver-related or kernel-level operations.

Core Stack Overview

In the Bluetooth software stack, the core protocols include the following components:

  • GAP (Generic Access Profile): Specifies how advertising and connection states are managed.
  • GATT/ATT (Generic Attribute Profile / Attribute Protocol): GATT defines the structure used for descriptions and the method of transmitting packets through ATT.
  • SMP (Security Manager Protocol):
  • SDP (Service Discovery Protocol): Protocol used to discover services under BR/EDR specifications.
  • L2CAP (Logical Link Control and Adaptation Protocol): Protocol used to abstract transport channels.
  • HCI (Host Controller Interface): Interface for actual hardware transmission.

Beneath HCI are the Link Manager (LM) and the firmware control layer responsible for baseband and radio functions.

BLE Advertising and Connection Flow

In BLE, the device sending advertisements is called the Advertiser, and the device receiving advertisements is called the Scanner.

When the advertising sends a Connectable advertisement, the initiating device (Initiator) sends an ACL connection request to establish a connection.

At this point:

  • The Advertiser will stop the advertising event upon receiving the connection.
  • After the connection is established, it will initiate a connection event based on the parameters.
  • The initiating device becomes the Central role, while the receiving device becomes the Peripheral role.

Bluetooth in Android AOSP (Fluoride)

The implementation of Bluetooth in Android AOSP is located in the Fluoride stack, which can be downloaded from Google Source:

🔗 Android Bluetooth Fluoride Source

After downloading, you can switch to a specific commit or tag, such as Android 12.1.0_r35:

git clone https://android.googlesource.com/platform/system/bt
cd bt
git checkout android-platform-12.1.0_r35

This allows you to explore the specific implementation of Bluetooth in Android AOSP.
